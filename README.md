# 岗位探索与求职准备助手

面向求职者的网页应用，用于保存目标岗位、理解JD、整理真实项目经历和准备面试。

## 当前实现

采用 Next.js、React、TypeScript、SQLite 和 Dexie 实现网页应用。账号及各自的岗位、项目、准备卡、比较、练习和计划保存在服务端；浏览器使用按账号隔离的缓存，登录同一账号可在其他浏览器继续准备。

- 岗位链接读取、动态页面读取、最多3张截图识别、正文解析，共用可编辑的校对界面；读取失败后保留链接并可换截图或正文。
- 岗位按方向分组，可搜索筛选、编辑、删除撤销，记录投递状态、投递与面试日期、结束原因和下一步行动。
- 职位类别依据JD的职责、工作方法和交付物判断，保留公司原始命名；“交互设计”“体验设计”等相近岗位可统一为用户体验设计，研究与视觉等相邻职位分别判断。新JD解析时同时归类，已有岗位和修改后的JD自动分析并直接保存分类，无需确认；在岗位详情查看JD依据、手动修改岗位类型或恢复自动识别。导航和清单不再提供独立的岗位归类、批量合并入口。产品岗位统一显示为“产品经理”，招聘类型“校园招聘”“校招”统一为“校招”，原始JD保持原文。分类信息随备份保存。
- DOCX、文字型PDF、扫描PDF、作品集与手动项目导入；事实核对、重复项目合并、项目阶段与脱敏展示预览。
- 真实模型按JD推荐、排序和改写项目；每条文字回指事实与岗位要求，增加事实语义核对，采用后可复制；支持手动事实组装与版本保存。
- 公司自动研究：围绕公司与JD规划搜索词，搜索并读取公开网页，提炼公司业务、岗位关联和待确认问题，保留原句、链接与读取时间。
- 首页展示当前目标、最近关注和准备进展；岗位清单独立提供筛选和整理；岗位详情独立导航并支持切换岗位，保留分步工作台。
- 宝蓝色工作台、可点击的准备路径、当前目标、岗位卡片和本周行动；按钮提供按压与保存反馈，进度对应实际保存的准备内容。视觉与交互参考[Duolingo的学习路径](https://blog.duolingo.com/new-duolingo-home-screen-design/)、[Brilliant的即时反馈](https://brilliant.org/faq/)和[Finch的小目标反馈](https://help.finchcare.com/hc/en-us/articles/37935669335309-Our-Approach-to-Self-Care)，采用轻度游戏化。
- 四栏准备卡，公开信息与业务方向推断分开呈现。
- 相近岗位及跨方向比较，准备事项加入本周计划，支持完成状态和手动排序。
- 文本面试、一次追问和分维度反馈；两项工作任务、同事消息、行动影响与复盘；新JD按职责生成任务，使用简洁的工作沟通风格。
- 账号注册、登录和退出，账号仅允许1—32位字母或数字，注册时忽略大小写检查重名。
- 账号资料自动保存及备份恢复；6个岗位样本和5个脱敏项目样本仅保存在管理员账号中，普通账号从空白资料开始。
- 手机使用固定底部导航及“更多”菜单，平板使用紧凑侧栏；表单、筛选与任务卡片按可用宽度换行。

AI功能需要在服务端配置百炼 `DASHSCOPE_API_KEY`，也支持原有 `CHAT_ECNU_API_KEY`。招聘网站需要登录、岗位已下线或限制读取时，使用截图或正文继续。示例岗位采用已核对的摘要，最新内容以来源招聘页为准。

## 账号与资料

首次启动会创建管理员 `admin / admin`，以及测试账号 `P01` 至 `P10`，密码均为 `123456`。仅管理员账号预置示例岗位和项目，后续更新不重置已有账号或资料。注册账号忽略大小写检查重复，密码至少6位，登录与注册都只有账号、密码两个字段。

密码使用带独立盐的 scrypt 摘要保存，登录凭据通过 HttpOnly Cookie 管理。业务接口在服务端检查登录及资料归属；即使管理员也只操作自己的工作台。HTTPS使用 Secure、SameSite=None、Partitioned Cookie，支持魔搭的嵌入页面。线上将 `APP_ORIGIN` 配置为实际应用地址，本机留空。

浏览器按账号保存缓存及未完成的保存操作，重新登录后继续提交。不同字段的并发修改可以合并；同一字段冲突时保留本页资料，提供重试、导出备份和重新读取。新账号从空白资料开始，不读取或导入旧版未分账号的浏览器资料。

## 配置与账号检查

复制 `.env.example` 为 `.env.local`，在本地填写令牌。`.env.local` 和 `.local/` 不提交到仓库，Docker构建也不读取这些文件。

```sh
node scripts/modelscope.mjs probe
node scripts/modelscope.mjs info JDtool
```

`probe` 只读取账号名称与Docker可用规格。`create` 仅选择明确标记免费的CPU资源并创建私有创空间，`deploy` 触发已有免费空间部署。后两项会修改远程资源。

首选百炼：在 `.env.local` 填写北京地域的通用 API Key，其他配置已有默认值：

```dotenv
DASHSCOPE_API_KEY=填入你的百炼APIKey
```

重启服务后，JD截图识别、岗位分析、项目准备和岗位体验默认使用 `qwen3.8-27b`。`MODEL_PROVIDER=auto` 在百炼 Key 非空时选择百炼，否则沿用 ChatECNU；也可指定 `bailian` 或 `chatecnu`。百炼调用失败不会自动换服务商或模型。`DASHSCOPE_MODEL` 可调整模型名称，替换时需同时确认图片输入、JSON输出和多模态联网搜索能力；`DASHSCOPE_BASE_URL` 默认北京地域兼容接口，也支持该地域业务空间专属域名。原有 `CHAT_ECNU_BASE_URL`、`CHAT_ECNU_MODEL` 继续有效。

百炼原生联网搜索复用同一 Key，无需额外搜索账号。`SEARCH_PROVIDER=auto` 按博查、Tavily、百炼顺序选择已配置的服务，也可指定 `bailian`、`bocha`、`tavily`。百炼采用多模态流式接口与 `turbo` 策略，每次公司研究最多两次搜索请求；只使用接口返回的搜索来源链接，实际读取网页后才分析，无法读取的标题不会被当作业务事实。原生搜索调用同样计入应用每日调用上限和并发上限。参考[百炼联网搜索文档](https://help.aliyun.com/zh/model-studio/web-search)和[结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

百炼模型免费额度以控制台所选模型和有效期为准，建议在控制台开启“免费额度用完即停”。联网搜索工具单独计费，不包含在模型免费 Token 额度中；如只使用模型免费额度，可设为 `SEARCH_PROVIDER=disabled` 关闭自动搜索，继续手动补充公司官网资料。参考[免费额度说明](https://help.aliyun.com/zh/model-studio/new-free-quota)。

部署时将 `DASHSCOPE_API_KEY` 写入创空间 Secrets，普通配置写入 Variables，避免把本地环境文件放进镜像。本地填写的密钥不会自动同步到线上。

独立搜索服务仍可使用 `BOCHA_API_KEY` 或 `TAVILY_API_KEY`。ChatECNU 对话接口已取消原生联网搜索，开放平台 `/search` 仅覆盖校内资料。参考[ChatECNU说明](https://developer.ecnu.edu.cn/vitepress/llm/api/completions.html)、[博查官方请求示例](https://open.bochaai.com/)和[Tavily接口文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

保存新岗位后首次打开会自动研究公司，已有结果在当前账号复用；点击“更新公司研究”重新搜索。一次研究最多两组搜索词，交替选择公司业务和岗位场景的结果；最多尝试十个公开网页，遇到登录或读取失败会继续尝试后续来源，最多保留四篇正文、合计六条来源。独立搜索服务提供了真实摘要但没有读到正文时明确标为“搜索摘要”；百炼只有标题和链接的来源需读到正文后才分析。搜索只使用公司和岗位信息，不包含简历与项目，不使用模型编造的链接。研究支持停止、重试与部分来源保留，沿用140秒总时限、每分钟限额与模型调用额度。网页读取校验公开IP、固定地址并校验跳转；分析条目需匹配来源原句，岗位关联还需引用当前JD要求。

尚未配置搜索或服务不可用时，显示重试和补充公司资料入口，岗位编辑、项目准备与练习仍可使用。完整线上搜索验收需要有效的搜索服务密钥。

`DAILY_MODEL_REQUEST_LIMIT` 默认200，统计每次实际模型调用；生成后的事实核对也计一次。`APP_DATA_DIR` 指向持久化目录，只存调用计数。另设每分钟请求限制与模型并发限制，日志省略用户正文和凭据。

一次生成及其事实核对共用140秒等待时限，浏览器等待180秒。取消请求会停止对应的上游调用；事实核对未完成的草稿保留在“需要确认的内容”，不自动成为可采用的最终文案。

项目修改后需重新核对相关表述，旧文案展示与复制都会应用当前脱敏规则。删除项目会清除用过该项目的生成文案及关联计划；早期记录没有输入项目版本时会清除相关类别的旧生成结果，岗位及其他原始项目会保留。备份恢复先完整校验再写入，有效事实的采用状态保留，事实已缺失或未确认时取消采用。

## ModelScope部署

选择 Docker 创空间，使用平台当前提供的免费CPU配置。应用监听 `0.0.0.0:7860`。当前空间：<https://modelscope.cn/studios/Eunomio/JDtool>。

Dockerfile包含生产构建、PDF识别资源与动态网页读取使用的 Chromium，支持后续迁移到其他Docker托管环境。`GET /api/health` 用于检查程序是否启动。账号、业务资料和调用额度保存在 `APP_DATA_DIR`；Docker默认为 `/mnt/workspace/jdtool`，本机默认为 `.local/accounts`。数据库不随代码上传。

GitHub仓库：<https://github.com/Eunomio/JDtool>。

浏览器测试覆盖桌面和手机尺寸下的链接与截图校对、失败接续、DOCX/PDF读取、项目确认、准备与组装、比较与计划、面试与剧情、删除撤销和备份恢复。Windows使用已安装的Edge，其他系统先执行 `npx playwright install chromium`。浏览器交互检查使用固定接口响应；真实模型与真实招聘链接另行验证，避免将交互检查当作识别准确率证明。
